# Demo Dossier Gold Annotations

## Purpose

This directory contains gold annotation files for the demo dossier at
`fixtures/demo_dossier/`. The files describe expected extractions,
deterministic findings, and negative tests for the shipped verify path.

These files are used for:

- demo-run regression detection
- recruiter/clone reproducibility of the local demo
- extraction recall/precision measurement (no committed numeric thresholds)
- checker recall and false-positive measurement (no committed numeric thresholds)

These files are **not** training data, are **not** used to set numeric pass
thresholds before calibration, and are **not** shared with `eval/synthetic_dossier/`.

## Isolation rule — `fixtures/gold/` vs `eval/synthetic_dossier/`

The benchmark-isolation rule is the most important property of this annotation
strategy. The two fixture trees measure different things:

| | `fixtures/gold/` (this dir) | `eval/synthetic_dossier/` |
|---|---|---|
| Purpose | Demo regression, buyer reproducibility, dev iteration | Locked ECO recall benchmark |
| Driven by | `scripts/run_demo.py` | `/eval` command (deferred) |
| Numeric thresholds | Deferred until post-calibration | Locked (per benchmark-isolation skill) |
| Annotation source | Span IDs against `fixtures/demo_dossier/` | Independent synthetic dossier (`eval/synthetic_dossier/`) |

**Never** copy demo gold into `eval/`. **Never** modify `eval/synthetic_dossier/`
when working in this directory. If the two converge, the eval becomes
self-referential and stops measuring anything.

## How these files were created

1. `scripts/seed_demo_fixture.py` regenerates the demo dossier deterministically.
2. `python -m locuslab.ingest.load_dossier` (via an inline script) was run
   against `fixtures/demo_dossier/` to produce real `Document` and `Span`
   records using the content readers (`docx_reader`, `pdf_reader`, `xlsx_reader`).
3. The resulting stable `document_id` and `span_id` values were copied into
   each `demo_*.json` file in this directory.
4. Expected claims, citations, bibliography entries, evidence links, numeric
   facts, expected findings, and negative tests were annotated **by hand**
   against the real text content visible in the spans.
5. The seed-script content hash below was recorded to invalidate gold files
   automatically if the seed script changes.

No LLM-assisted annotation. No external SaaS. Local-only.

## Fixture pin

The demo dossier is regenerated by `scripts/seed_demo_fixture.py`. If that
file changes, the gold files in this directory must be reviewed and likely
regenerated.

- `scripts/seed_demo_fixture.py` SHA-256 at annotation time:
  `e4a99e69f61a1539022eb9cc0209a9eb8b2274b131fd50f6993e5555340abbc3`
- Annotation date: 2026-05-22
- Ingestion produced: 4 documents, 48 spans, 1 parser warning (README.md,
  expected — unsupported file type)
- Annotator: founder review against real spans from the content readers

To recompute the pin:

```bash
python -c "import hashlib; print(hashlib.sha256(open('scripts/seed_demo_fixture.py','rb').read()).hexdigest())"
```

## Span ID stability warning

Every `span_id` referenced in these gold files is a function of:

- `document_id` (derived from `kind`, `relative_path`, `sha256`)
- `SpanLocation.kind`, `index`, `label`
- the exact extracted text

If any of these inputs change — fixture regeneration with different content,
reader changes that alter paragraph indexing or table cell labeling, or text
normalization — the IDs in this directory become stale.

When that happens:

1. Re-run the ingestion against `fixtures/demo_dossier/`.
2. Re-pin the seed-script SHA-256 above.
3. Update every `document_id` / `span_id` in the JSON files.
4. Re-read each annotation rationale — text-fragment expectations may also need
   to change.
5. Treat gold-file edits as PR-reviewable. Do not regenerate silently.

## Schema notes

These gold files are **JSON only** and intentionally do not import or extend
production dataclasses in `src/locuslab/models.py`. They mirror the *concepts*
(claim type, severity, ECO IDs, availability status) but use plain string
values so that gold remains reviewable, diffable, and decoupled from internal
refactors of the production models.

Each record carries a `gold_id` that is independent of pipeline-generated IDs,
so fixture regeneration does not invalidate annotation references as long as
the seed script remains deterministic.

## Files in this directory

| File | Purpose |
|---|---|
| `README.md` | This file |
| `demo_documents.json` | Expected documents from ingestion (regression check) |
| `demo_spans.json` | Expected per-document/section span coverage (regression check) |
| `demo_claims.json` | Selective claim candidates the shipped extractor must surface |
| `demo_citations.json` | In-text citation mentions found in CER.docx |
| `demo_bibliography.json` | Bibliography/source records and resolution targets |
| `demo_evidence_links.json` | Expected claim → source links and unresolved cases |
| `demo_numeric_facts.json` | Numeric values for rate/CI/denominator checks |
| `demo_expected_findings.json` | Exact seven-finding contract for the demo run |
| `demo_negative_tests.json` | Inputs checkers SHOULD NOT fire on (FP-rate measure) |

`demo_expected_findings.json` and `demo_negative_tests.json` measure different
properties (recall vs false-positive rate) and **must not** be merged or
cross-referenced. Merging them makes both metrics undefined.

## Severity discipline

Severity in `demo_expected_findings.json` follows the ECO rule, not the demo's
narrative impact:

- **Critical** — reserved for deterministic contradictions affecting central
  safety/performance conclusions on a real claim. Synthetic findings on this
  fixture do not qualify.
- **Major** — deterministic contradictions (numeric mismatch beyond tolerance,
  malformed structure) or serious unresolved evidence.
- **Minor** — structural or local issues, completeness gaps without direct
  evidence-link consequence.
- **Informational** — review notes; no compliance conclusion.

Language follows the `no-confident-verdict-without-evidence` rule. Findings
without deterministic evidence use *potentially unsupported*, *unresolved
evidence link*, *requires manual review* — never *non-compliant*, *false
claim*, *NB will reject*, or *regulatory failure*.

## Updating procedure

1. If `scripts/seed_demo_fixture.py` changes, rerun
   `python scripts/seed_demo_fixture.py` to regenerate the dossier files.
2. Run the ingestion (a small Python helper that calls `load_dossier`).
3. Diff old vs new span IDs.
4. Update document_id/span_id references in every `demo_*.json` file.
5. Re-pin the seed-script hash in this README.
6. Submit as a reviewable change. Do not auto-regenerate.

## Executable contract

`tests/test_demo_gold_diff.py` resolves the selective gold annotations against
the live claims, citations, sources, evidence links, and findings. Every
annotated object must match exactly once. This is a regression contract for
the shipped demo, not a calibrated performance threshold or an independent
benchmark.
